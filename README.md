# 资产管理平台

一个为制造业公司打造的企业级资产管理系统。从零开始，用现代技术栈搭了一套能真正用起来的东西。

## 这是个什么项目？

简单说，就是帮公司管理固定资产的系统。笔记本电脑、显示器、办公设备这些，谁在用、放哪了、借出去了没还——这些琐碎但重要的事，都能在这里搞定。

最开始是因为公司的资产管理还停留在 Excel 阶段，几百上千条记录要查个东西得翻半天。更头疼的是，借用、归还、调拨这些流程没法追溯，经常不知道设备到底在谁手里。所以就想着做个系统把这些流程理顺。

### 核心功能

**资产全生命周期管理**
- 资产台账：编号、名称、分类、位置、使用人等完整信息
- 多维度搜索：支持关键词、状态、位置、使用人等快速定位
- 资产详情：一键查看完整历史轨迹（领用、借用、调拨、变更记录）

**业务单据流程**
- 领用/借用单：员工申请、多级审批、自动更新资产状态
- 调拨单：跨部门/跨地点的资产转移
- 变更单：资产信息修正（位置、使用人等）
- 退还流程：借用到期自动提醒，退还后状态回归

**审批与通知**
- 灵活的审批链配置（支持部门主管、仓管员等多角色）
- 站内通知中心（实时推送审批任务、抄送消息）
- 钉钉 OA 集成：审批流程与钉钉打通，移动端随时处理

**移动端支持**
- 响应式设计，手机浏览器直接用
- 扫码功能：通过二维码/条形码快速查找资产
- 移动审批：随时随地处理待办

## 技术栈

这个项目用的都是目前主流的技术，写起来顺手，维护起来也不累。

### 后端 (backend/)

- **Java 17 + Spring Boot 3**：现代化的 Java 开发体验
- **MyBatis-Plus**：比直接写 SQL 方便太多，CRUD 基本不用手写
- **MySQL**：关系型数据库，稳定可靠
- **Flyway**：数据库版本管理，每次变更都有迹可循
- **钉钉 Open API**：对接企业钉钉，实现免登、审批、消息推送

**架构设计亮点**
- 统一鉴权：复用公司已有的权限中心，不用重复造轮子
- 审批引擎：站内审批 + 钉钉审批双向同步，一套逻辑两端适配
- 事件驱动：钉钉审批回调通过 Stream 推送，实时性好

### 前端 (frontend/)

- **Vue 3 + TypeScript**：类型安全，代码提示友好
- **Vite**：开发时热更新快到飞起
- **Pinia**：状态管理简洁明了
- **Ant Design Vue**：组件库成熟，UI 不用从零搭
- **Nginx**：生产部署用，轻量高效

**前端特色**
- Composition API：逻辑复用方便，代码组织清晰
- 响应式布局：PC 和移动端用同一套代码
- 命令面板（Cmd+K）：快速导航，效率拉满
- 多 Tab 页签：类似 IDE 的体验，在不同页面间切换不丢状态

### 工程化

- **Docker + Docker Compose**：一键部署，环境隔离
- **GitLab CI/CD**：自动化构建部署
- **代码规范**：ESLint + Prettier 保证代码风格统一

## 快速开始

### 前置要求

- JDK 17+
- Node.js 18+
- MySQL 8.0+
- Docker（可选，用于容器化部署）

### 本地开发

**1. 克隆仓库**

```bash
git clone https://github.com/sirpinaple1/asset-management-platform.git
cd asset-management-platform
```

**2. 后端启动**

```bash
cd backend

# 配置数据库（复制示例配置，修改数据库连接信息）
cp src/main/resources/application-local.yml.example src/main/resources/application-local.yml
# 编辑 application-local.yml，填入你的数据库地址、用户名、密码

# 运行（Flyway 会自动创建表）
mvn spring-boot:run
```

后端服务会在 `http://localhost:6006` 启动。

**3. 前端启动**

```bash
cd frontend

# 安装依赖
npm install

# 配置环境（复制示例配置）
cp .env.development.example .env.development
# 如果后端不在 localhost:6006，修改 .env.development 里的 VITE_PROXY_TARGET

# 启动开发服务器
npm run dev
```

前端会在 `http://localhost:5173` 启动，自动代理 API 请求到后端。

**4. 访问系统**

打开浏览器访问 `http://localhost:5173`，默认管理员账号见后端日志或数据库初始化脚本。

### Docker 部署

```bash
# 前端构建
cd frontend
npm install
npm run build

# 启动服务（包含 MySQL、后端、前端）
docker-compose up -d
```

## 一些设计决策

### 为什么选 Spring Boot 3？

Spring Boot 3 基于 Spring Framework 6，原生支持 Jakarta EE（不再是 javax.*），虚拟线程等新特性未来可期。虽然迁移成本有点，但长期维护角度看是值得的。

### 为什么用 Flyway 而不是手动建表？

手动建表在开发初期还行，但一旦有多人协作或者多环境部署（开发、测试、生产），数据库版本就容易乱。Flyway 让每次表结构变更都有版本号和 SQL 脚本，回滚、升级都清清楚楚。

### 前端为什么不用 React？

主要是团队熟悉度，Vue 的上手曲线更平缓。而且 Vue 3 的 Composition API 写起来和 React Hooks 其实挺像的，类型支持也不错。

### 钉钉集成有多深？

目前主要是三块：
1. **免登**：钉钉内打开系统自动登录，不用再输账号密码
2. **审批流**：发起审批可以走钉钉，审批人在钉钉待办里处理，结果同步回系统
3. **消息推送**：审批状态变化、任务提醒等通过钉钉工作通知推送

没有完全绑死钉钉，站内审批流程也能用，只是钉钉集成能让使用体验更好。

## 开发心得

这个项目从最初的需求调研、技术选型，到完整实现上线，前前后后大概两个多月。有些经验分享一下：

**数据库设计很重要**  
一开始没想清楚，后来改表结构很痛苦。建议先把核心实体（资产、单据、审批）的关系理顺，写个 ER 图，再开始建表。

**前后端分离的协作成本**  
接口定义要提前约定好，字段名、数据类型、错误码这些最好统一。我是后端写完接口直接生成 OpenAPI 文档，前端照着文档对接，减少扯皮。

**审批流没想象中简单**  
起初以为审批就是"提交 → 审批人点同意/拒绝"，实际场景复杂得多：多级审批、并行审批、回退、转交、超时自动通过……最后抽了个审批引擎，把这些逻辑封装起来。

**移动端适配没那么难**  
用 Ant Design Vue 的栅格系统，PC 和移动端用同一套组件，只是布局调一下。关键是要实际在手机上测，很多问题桌面浏览器看不出来。
