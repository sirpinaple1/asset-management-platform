# 资产数据流转说明

> 本文描述一件资产在系统内被**领用（含借用）、退库（归还）、调拨**时的完整数据流转。
> 依据代码：M04 领用/借用（`ReceiveReceiptServiceImpl`）、持有关系（`AllocationServiceImpl`）、M05 调拨（`TransferOrderServiceImpl`），含 B1 定向待办 / B2 通知扩展。

## 0. 核心数据模型

| 表 | 角色 | 关键字段 |
|---|---|---|
| `asset` | 资产主档（唯一权威归属） | `status`、`user_id`（现持有人）、`user_department`、`location_id` |
| `receive_receipt` / `receive_receipt_item` | 领用·借用单（主表+明细） | `type`(RECEIVE/BORROW)、`status`(PENDING/APPROVED/REJECTED)、`assignee_user_id` |
| `transfer_order` / `transfer_order_item` | 调拨单 | `to_location_id`、`to_user_id`、`to_department` |
| `asset_allocation` | 持有关系流水（"现在在谁手里"） | `asset_id`、`user_id`、`type`(RECEIVE/BORROW/TRANSFER/CHANGE)、`returned_at`(NULL=持有中) |
| `asset_log` | 资产操作日志（每次流转必写） | `operation_type`（领用/借用/归还/调拨/报废…） |
| `sys_notification` | 站内通知（B2） | `user_id`、`type`、`biz_type`、`biz_id` |

**资产状态机**（`AssetStatus`，非法流转直接 409 回滚）：

```
新增 → IDLE
IDLE ──→ IN_USE（领用通过）/ DISCARD（报废）/ PENDING_CONFIRM（发起申请）
IN_USE ─→ IDLE（归还）/ DISCARD（报废）/ PENDING_CONFIRM（发起申请）
PENDING_CONFIRM ──→ IN_USE（审批通过）/ IDLE（审批拒绝）
DISCARD = 终态
```

**两条不变式**：所有状态变更只经 `AssetService.changeStatus()`（同时写 `asset_log`）；所有写操作在 `@Transactional` 内，任一步失败整体回滚。

## 1. 领用 / 借用（ARE / BOR 单）

领用与借用共用同一单据流，仅单号前缀与展示语义不同（借用中也算 IN_USE）。

### 1.1 发起申请 `POST /api/v1/receipts`

前置校验（任一失败即 400/409，不产生任何写入）：

1. 指定处理人校验（B1）：`assigneeUserId` 不能是申请人自己（死单防御），且必须存在于 comm_public_basic `sys_user`
2. 资产存在性；至少一台
3. 占用互斥：同一资产同时只能挂在一张 PENDING 单上——领用/借用、调拨、变更三类单互斥占用
4. 领用区域（`locationId`）必填且存在

写入（单事务）：

```
receive_receipt   : 插入主表（PENDING，单号 = 前缀+日期+序号，FOR UPDATE 串行取号）
receive_receipt_item : 每台资产一行明细
asset             : IDLE/IN_USE → PENDING_CONFIRM（写日志"发起申请，待审批"）
sys_notification  : 定向单通知 assignee（共享池单据无定向接收人，不通知）
```

### 1.2 审批 `POST /api/v1/receipts/{id}/approve | reject`

门禁：单据必须 PENDING；审批人 ≠ 申请人；`assigneeUserId` 非空时审批人必须是 assignee（NULL=共享池，任何非发起人可审）。

**通过**（单事务）：

```
asset             : PENDING_CONFIRM → IN_USE（每台写日志）
asset             : user_id = 申请人，user_department = 申请部门，location_id = 领用区域
asset_allocation  : 每台插入一条持有记录（type=RECEIVE/BORROW，returned_at=NULL）
receive_receipt   : 状态 → APPROVED，记录审批人/时间
sys_notification  : 通知申请人"已通过"
```

**拒绝**（单事务）：

```
asset             : PENDING_CONFIRM → IDLE（每台写日志，含拒绝原因）
receive_receipt   : 状态 → REJECTED
sys_notification  : 通知申请人"已拒绝"（含原因）
```

**领用通过后，这件资产的完整画像**：`asset.status=IN_USE`、`asset.user_id=领用人`、一条 `returned_at IS NULL` 的 allocation、一条 APPROVED 的 ARE/BOR 单、一条"领用"日志。

## 2. 退库 / 归还（无独立单据，直接操作持有记录）

领用退库与借用归还共用同一入口：`POST /api/v1/allocations/{id}/return`。
前端从 `GET /api/v1/allocations?active=true`（持有中列表）拿到 allocation id。

单事务内三步（`AllocationServiceImpl.returnAllocation`）：

```
asset_allocation : returned_at = now（该持有记录闭环；重复归还 409）
asset             : IN_USE → IDLE（写"归还"日志，含原持有人）
asset             : user_id/user_department 清空——仅当持有人仍 = 本记录持有人
                    （期间已被调拨/变更转让给他人则不动，防误清新持有人的归属）
```

归还不需要审批，操作人即当前登录用户（资产管理员代退或本人退库）。

**归还后画像**：`asset.status=IDLE`、`asset.user_id=NULL`、allocation 的 `returned_at` 非空（历史持有可追溯）、一条"归还"日志。

## 3. 调拨（ATR 单）

调拨 = 把资产从一个归属（人/部门/区域）转到另一个归属。发起时**不锁定资产状态**；确认时才做联动。

### 3.1 发起 `POST /api/v1/transfers`

调拨方向二选一（由填写的调入字段决定）：

- **填使用人/部门** → 持有转移（终态 IN_USE）
- **只填调入区域** → 回库（终态 IDLE，持有人归零）

写入（单事务）：

```
transfer_order / transfer_order_item : PENDING（单号 ATR+日期+序号）
asset                                 : 状态不变（撤销/拒绝资产不受影响）
sys_notification                      : 定向单通知 assignee
```

发起人可在 PENDING 期间撤销（`cancel`，仅发起人可操作，资产不变）。

### 3.2 确认 `POST /api/v1/transfers/{id}/confirm`

门禁同领用：PENDING + 非发起人 + assignee 门禁；逐台校验资产存在且未报废。

每台资产五步（`confirmAsset`，单事务）：

```
1. 状态联动（走状态机，同态跳过）：有新持有 → IN_USE；回库 → IDLE
2. 闭环旧持有记录：该资产所有 returned_at IS NULL 的 allocation 打上 returned_at
   （note="调拨单 xxx 调出，持有关系随调拨终结"）
3. 更新资产归属：location → 调入区域；持有转移则 user_id/user_department = 调入方，
   回库则清零（与 IDLE 终态对齐，不留悬死归属）
4. 新建调入方持有记录（type=TRANSFER）：填使用人 → 人持有；只填部门 → 部门持有（user_id=NULL）
5. 写调拨明细日志：【字段】由【旧值】变更为【新值】
```

收尾：`transfer_order → COMPLETED`，通知发起人"已确认完成"（DOC_COMPLETED）。

**拒绝**：仅记录处理人/原因，资产与持有关系完全不变；通知发起人（DOC_REJECTED）。

## 4. 全景流转图

```
                    发起领用/借用                审批通过
   ┌─────────┐  ───────────────→  ┌───────────────┐  ──────→  ┌────────────┐
   │  IDLE   │                    │ PENDING_CONFIRM│           │   IN_USE   │
   └─────────┘  ←───────────────  └───────────────┘  ←──────   └────────────┘
        ↑            审批拒绝            ↑                    发起领用/借用  │
        │                                                 ┌───────────────┤
        │              归还 /return                        │               │
        └─────────────────────────────────────────────────┘               │
        ↑              调拨回库（只填区域）                                  │
        └─────────────────────────────────────────────────────────────────┘
                                  调拨确认（填使用人/部门）：IN_USE 不变或 IDLE → IN_USE

  持有关系（asset_allocation）：
    领用通过     : +RECEIVE/BORROW 记录（returned_at=NULL）
    归还         : 该记录 returned_at=now
    调拨确认     : 旧记录全部闭环 + （持有转移时）+TRANSFER 新记录
    任意时刻     : 一台资产最多一条 returned_at IS NULL 的记录
```

## 5. 并发与一致性保障

| 机制 | 作用 |
|---|---|
| 单号 `SELECT ... FOR UPDATE` 串行取号 + 唯一键兜底 | 并发发起不重号 |
| PENDING 占用互斥校验（三单互查） | 同一资产不会同时进两张在途单 |
| 状态机 `canTransitionTo` 硬校验 | 非法流转（如 DISCARD → IDLE）409 整体回滚 |
| `@Transactional(rollbackFor = Exception.class)` | 单据/资产/持有/日志/通知要么全成要么全无 |
| 归还时 `user_id = 原持有人` 条件更新 | 资产已被转让给他人时不误清归属 |
| 审批门禁（非发起人 + assignee） | 防自审自批；定向单只有指定处理人能操作 |
