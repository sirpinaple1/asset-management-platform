# ADR-0007 — 钉钉 OA 审批双向集成（实验公司验证 → 生产切换）

- 状态：Proposed
- 日期：2026-08-31
- 决策者：用户（王五）

## 背景

资产系统的领用/借用/调拨/退库/实物变更等单据流程目前只在系统内闭环（B4 已落地两级审批链）。业务方日常在钉钉上办公，希望：

1. 系统内创建的单据自动在钉钉生成 OA 审批（含抄送），审批人直接在钉钉上处理；
2. 钉钉上发起的 OA 审批（如 IT 资产退还单），审批同意后实时回传系统执行业务动作；
3. 集成连接全部配置化，先在**实验公司**（瀚海长航有限公司，单人）验证，验证通过后仅改配置即可切到正式生产公司。

约束：

- 单模块 Spring Boot 单实例（ADR-0005），无公网 IP/域名的部署形态（CI 沙箱）；
- 鉴权复用 comm_public_basic（ADR-0004），asset 不自建用户体系；
- comm_public_basic 的 `sys_user.dd_user_id` 已存钉钉 userId（`loginByDingTalk` / `bindDingTalkUser` 已就绪），是天然的账号映射锚点。

## 决策

### D1. 集成通道：钉钉企业内部应用 + 官方 OA 审批 OpenAPI + Stream 事件订阅

- **发起审批**：新版服务端 API `POST /v1.0/workflow/processInstances`（权限 `Workflow.Instance.Write`），审批人与抄送人由 API 参数指定；
- **状态回传**：事件订阅 **Stream 模式**（WebSocket 长连接），订阅 `bpms_task_change`（任务级，推进两级审批）与 `bpms_instance_change`（实例级，终态/撤销）；
- **实例详情**：`GET /v1.0/workflow/processInstances/{instanceId}`（权限 `Workflow.Instance.Read`），事件信息不足时回查；
- **访问凭证**：`POST /v1.0/oauth2/accessToken`（appKey/appSecret 换取，本地缓存至过期）。

### D2. 审批人由 API `approvers` 指定，不复用 OA 后台流程（系统发起路径）

系统发起的 OA 实例通过 `approvers` 传入**系统审批链快照**对应的钉钉 userId（两级 = 两个 AND 顺序节点；两级同人为一个节点）。理由：审批链解析/冻结/同人合并语义已在 `ApprovalChainResolver` 实现（B4），OA 后台静态流程无法按单据动态指定，二者必然漂移。

钉钉端**人工发起**的表单（如退库单）则复用 OA 后台配置的流程——同一模板两种用法互不冲突（不传 `approvers` 即走后台流程）。

### D3. 账号映射：复用 comm_public_basic `sys_user.dd_user_id`

- asset 经现有 `app.user-directory` 只读连接查询 `comm userId → dd_user_id` 映射，Caffeine 缓存（5 分钟）；
- 不在 asset 库新建映射表，避免双写漂移；
- 未绑定钉钉的用户参与审批链时：该单据 OA 同步降级为失败（记录 + 通知管理员），系统内审批不受影响。

### D4. 一致性模型：本地单据是唯一事实源（source of truth）

- **系统 → 钉钉**：事务提交后（`afterCommit`）异步创建 OA 实例，`oa_instance` 表记录同步状态（outbox 模式），失败可重试；
- **钉钉 → 系统**：事件按 `eventId` 幂等去重（`oa_event_log` 表），处理后仍通过**现有状态机唯一漏斗**（approve/reject/changeStatus）落地；
- 双端并发审批（系统内点了同意、钉钉事件也到达）：状态机 + 单据状态守卫裁决，先到先得、后到幂等丢弃并记日志。

### D5. 配置化切换：`app.dingtalk.*` 全外置

appKey/appSecret/agentId/corpId 与各单据类型的 `processCode` 全部走 `application-{env}.yml` / 环境变量（R3 红线：密钥不入库）。实验公司 → 生产切换 = 换一套配置 + 在新公司建模板/应用，**代码零改动**。`enabled=false`（默认）时集成整体关闭，系统功能不受影响。

### D6. 新增 `integration/dingtalk` 上下文包，与 `auth` 包同级

钉钉客户端属于基础设施端口（类比 `auth/AuthPort`）：service 层依赖它，controller 不直接依赖。分层红线（R1）不破坏。

## 备选方案

| 备选 | 不选原因 |
|---|---|
| HTTP 回调模式接收事件 | 需要公网 IP/域名 + AES 加解密 + 验签，单实例部署无此资源；Stream 官方推荐且免资源 |
| 待办 workrecord（`topapi/process/workrecord/create`） | 只能创建"待办任务"，不能在钉钉原生审批中心 agree/refuse 并回传结果，无法满足双向联动 |
| 不传 `approvers`、复用 OA 后台审批流 | 后台流程静态配置，无法按单据动态指定两级审批人快照，与 B4 审批链冻结语义冲突 |
| 由 comm_public_basic 统一承接钉钉集成 | 审批业务语义（单据/状态机/审批链）全在 asset；comm_public_basic 只管身份。且红线要求 comm_public_basic 保持只 HTTP 调用、不引入业务依赖 |
| asset 库新建钉钉用户映射表 | 与 `sys_user.dd_user_id` 双写漂移风险；只读映射直接查源即可 |

## 后果

**正面**：

- 免公网资源、配置化切换、复用现有审批链与状态机，实验公司验证的代码可直接上生产；
- 钉钉审批成为系统审批的"另一入口"而非平行体系，无双轨数据。

**负面 / 约束**：

- 钉钉**标准版** OpenAPI 配额约 1 万次/月、Stream 事件推送约 5000 次/月，生产用量需评估，超限需升级钉钉付费版（专业版 50 万次/月）——**上线前必查生产公司钉钉版本**；
- comm_public_basic 的钉钉绑定能力以 **GitLab 原始版为准**（本地私改版确认有 `dd_user_id`/绑定接口，生产版需核实，AGENTS.md 既定约定）；
- 新增依赖：钉钉官方 SDK（stream 客户端 + workflow client），引入前必须过 License 检查（R6，钉钉官方 Java SDK 为 Apache-2.0，预计合规，落地时核实）；
- 新增 2 张表（`oa_instance` / `oa_event_log`）与 1 个上下文包；外部 HTTP 依赖使测试必须 mock/WireMock；
- 钉钉侧人工发起的表单无法从系统选资产（无资产选择控件），只能填资产编码，系统侧需校验并经评论/待办反馈错误。
