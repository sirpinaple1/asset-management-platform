# ADR-0006 — 数据库核心表设计（基于参考系统对比）

- 日期：2026-08-19
- 状态：Accepted
- 决策人：用户 + Claude Code（决策层会话）

## 背景

对比 Snipe-IT（国际标杆）和 Ciyo ciyo-itasset（国内参考，已读源码），结合现有系统 Excel
导出分析（563 条资产、346 条领用单、56 条调拨单、1775 条操作日志），对 2026-08-18 草案进行修订。

## D1. 增加 `asset_model`（型号）中间层

**问题**：草案直接 `asset → category`，两个参考系统都在中间插入 model 层。

**决策**：`asset → asset_model → (asset_category + manufacturer)`

理由：同型号批量资产共享规格/折旧规则/分类；折旧规则挂在 model 上，是后期折旧模块正确运行的前提。

```
asset_model(id, name, model_number, category_id, manufacturer_id,
            depreciation_id nullable, eol_months nullable,
            notes, deleted, company_id, created_at, updated_at)
```

## D2. 拆分 vendor 为 `manufacturer`（厂商）+ `supplier`（供应商）

草案只有一个 `vendor` varchar。`asset_model` 关联 `manufacturer`（谁生产），`asset` 关联 `supplier`（从谁购买）。

## D3. 增加 `asset.home_location_id`（归属位置）

借鉴 Snipe-IT `rtd_location_id`：`location_id` = 当前位置，`home_location_id` = 应归放位置（可为空）。

## D4. 增加 `asset_allocation` 表（持有关系追踪）

借鉴 Ciyo `itam_allocations`。与 `receive_receipt` 互补：

- `receive_receipt`：有审批流的 ARE 单据，是操作记录
- `asset_allocation`：当前持有关系快照，方便查询"现在在谁手里"

```
asset_allocation(id, asset_id, user_id, department, allocated_at,
                 returned_at nullable, note, company_id, created_at)
```

## D5. 增加 `depreciation_rule` 表（结构预留，逻辑 Phase 4 再实现）

```
depreciation_rule(id, name, method varchar(20), useful_life_months int,
                  salvage_rate decimal(5,2), deleted, company_id, created_at, updated_at)
```

`asset_model.depreciation_id` FK 到此表。折旧计算逻辑列为最低优先级。
