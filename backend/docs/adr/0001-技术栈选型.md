# ADR-0001 — 技术栈选型

- 状态：Accepted
- 日期：2026-08-18
- 决策者：项目 Owner

## 背景

资产管理系统需自研替代 yideamobile，覆盖 IT 资产、固定资产、生产设备/工装、耗材四类，含全生命周期、折旧、移动扫码盘点。团队已有 WMS/MES 项目经验（Java Spring Boot + MySQL + Vue + uni-app）。需选定一套高可维护、可承接、团队熟悉的技术栈。

## 决策

- **后端**：Spring Boot 3.4 + JDK 17 + MySQL 8+
- **前端**：Vue 3.5 + Vite + TypeScript + Element Plus + Pinia
- **数据库迁移**：Flyway
- **API 契约**：OpenAPI 3
- **测试**：JUnit5 + Mockito + Testcontainers + ArchUnit

## 备选方案

- 若依 RuoYi 脚手架：权限/代码生成器成熟，但框架较重、代码风格固化，DDD 落地受限。未选，仅作为业务模型参考来源之一。
- FastAPI（Python）：开发快，但与团队既有 Java 栈割裂，运维与复用成本高。未选。
- React + Ant Design：更现代，但团队 Vue 经验更深，切换成本不值。未选。

## 后果

- 正面：与团队 WMS/MES 技能栈一致，可复用部署/鉴权/运维经验；Java 生态成熟，招人易。
- 负面：Spring Boot 3 要求 JDK 17，部分老库需评估兼容性。
- 约束：前端 Element Plus 与 Vue3.5 强绑定，组件升级需关注 breaking change。
- 后续：uni-app 用于移动扫码盘点端（复用 new_app_mes 经验），作为独立子工程。
