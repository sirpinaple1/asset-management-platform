# 资产细化到人的台账系统 OA 完整解决方案

> 版本：v1.0（2026-08-27）
> 定位：固定资产/IT 数码资产"**责任到人**"的全生命周期台账管理 OA 方案。

---

## 1. 背景与目标

### 1.1 业务痛点

| 痛点 | 本方案对策 |
|---|---|
| 资产"在账不在人"——只知数量不知在谁手里 | 持有关系双轨制（§3.1），任意时刻可答"这台资产现在谁负责" |
| 责任界定模糊——离职/转岗后资产无人接管 | 持有闭环 + 离职对账（§6.2），持有记录不闭环则人走账不清 |
| 台账与实物脱节——账面位置 ≠ 实际位置 | 领用必填区域 + 盘点差异自动触发调拨（§5.6） |
| 操作无凭据——纠纷时说不清何时何人经手 | 单据 + 资产日志双链路全程留痕（§3.4） |
| 审批流转靠口头/微信 | 三类单据电子审批流 + 定向待办 + 站内通知（§5、§7） |

### 1.2 目标

一台资产从**入库 → 领用 → 使用 → 调拨/变更 → 归还/报废**的每一步：

1. **有人**：`asset.user_id` 始终指向当前责任人（闲置时为 NULL）；
2. **有据**：每次归属变化必有单据（ARE/BOR/ATR/AOC）或持有记录背书；
3. **有痕**：`asset_log` 记录【字段】由【旧值】变更为【新值】，全程可回放；
4. **可对账**：任意时刻"一人名下持有清单"、"一台资产经手历史"两条查询秒出。

## 2. 总体架构

```
┌─────────────────────────────────────────────────────────────┐
│  auth-center（comm_public_basic 统一门户，已有系统）           │
│  登录/组织架构/角色/token（Redis）——asset 不自建用户体系        │
└──────────────┬──────────────────────────────────────────────┘
               │ Bearer token + systemCode:asset（HTTP 解耦）
┌──────────────┴──────────┐   ┌──────────────────────────────┐
│ asset-frontend (Vue3)   │   │ asset-backend (Spring Boot 3)│
│ 工作台/审批中心/资产台账  │   │ 6006 端口，单模块三层         │
│ 五类单据/盘点/基础数据    │   │ MyBatis Plus + Flyway        │
│ 通知铃铛/迁移工具页       │   │ Knife4j API 文档             │
└──────────────┬──────────┘   └───────┬───────────┬──────────┘
               │ REST /api/v1         │           │ 只读 JDBC
               └──────────────────────┘           │（用户目录）
┌──────────────────────────────┐   ┌─────────────┴────────────┐
│ db_sk_asset（19+ 核心表）     │   │ db_comm_public_basic     │
│ 资产/单据/持有/日志/通知/盘点  │   │ sys_user（姓名/工号/部门） │
└──────────────────────────────┘   └──────────────────────────┘
```

**架构原则**（ADR-0004/0005）：

- 鉴权复用 comm_public_basic，asset 库**不存用户主数据**，只存**业务时点快照**（applicant_name/user_name 等）——人事变动不影响历史单据展示；
- 单模块三层（controller/service/mapper），按业务上下文分包（receipt/transfer/change/stocktake/notification/stats）；
- 资产状态变更只有一个入口 `AssetService.changeStatus()`，写库必写日志。

## 3. "细化到人"的核心数据设计

### 3.1 归属双轨制 ✅

| 轨道 | 载体 | 回答的问题 | 更新时机 |
|---|---|---|---|
| **现状轨** | `asset.user_id` / `user_department` / `location_id` | 这台资产**现在**在谁手里、在哪 | 审批通过/调拨确认/变更确认/归还/报废，与状态机同事务更新 |
| **历史轨** | `asset_allocation`（持有流水） | 这台资产**曾经**被谁持有多久 | 每次持有建立插一条，终结时打 `returned_at` |

**不变式**：一台资产任意时刻**最多一条** `returned_at IS NULL` 的持有记录；`asset.status=IN_USE` 时必有持有记录，`IDLE` 时持有记录全部闭环（报废联动闭环保证，2026-08-21 修复）。

### 3.2 资产状态机 ✅

```
新增 → IDLE（闲置库）
IDLE ──────→ PENDING_CONFIRM ──通过──→ IN_USE（在用，user_id=领用人）
IN_USE ────→ PENDING_CONFIRM ──拒绝──→ IDLE / 归还 / 调拨回库
任意(非终态) → DISCARD（报废，终态；在用报废自动闭环持有）
```

- 非法流转（如 DISCARD→IDLE）由 `canTransitionTo` 硬校验 409，事务整体回滚——**台账状态永远合法**，这是对账可信的根基。
- 调拨不流转到 PENDING_CONFIRM（发起不锁资产），确认时按终态直达：填使用人/部门 → IN_USE，只填区域 → IDLE 回库。

### 3.3 单据族 ✅

| 单据 | 表 | 单号前缀 | 审批语义 | 归属动作 |
|---|---|---|---|---|
| 领用单 | receive_receipt(type=RECEIVE) | ARE | 他人审批（可定向 assignee） | 通过后 user_id=申请人 + 建持有 |
| 借用单 | receive_receipt(type=BORROW) | BOR | 同上 | 同上（借用期也算 IN_USE） |
| 调拨单 | transfer_order | ATR | 调入方确认（非发起人） | 闭环旧持有 + 按终态建新持有/回库 |
| 变更单 | change_order | AOC | **允许发起人自审**（信息修正性质） | 使用人变化时同步持有关系 |
| 盘点任务 | stocktake | — | 无审批，创建人主导 | 差异生成 INVENTORY_TRIGGERED 调拨 |

三类在途单据（PENDING）对同一资产**互斥占用**——同一台资产不可能同时进两张单，杜绝"一物二主"。

### 3.4 全程留痕 ✅

- `asset_log`：状态流转日志（领用/借用/归还/调拨/报废/盘点处理）+ 明细变更日志（【字段】由【旧值】变更为【新值】），`diff_json` 存结构化差异；
- 单据快照：申请人/审批人/持有人姓名在单据创建时点快照落库，永不随组织变动漂移；
- `GET /api/v1/assets/{id}/logs` 一键回放这台资产的完整经手史。

## 4. 角色与权限

### 4.1 角色（comm_public_basic 统一管理）✅

| 角色 | 职责 | 关键操作 |
|---|---|---|
| asset-资产管理员 | 台账Owner：基础数据、资产建档、审批、盘点、报废 | 全部端点（迁移工具双重门禁亦限此角色） |
| 普通员工 | 申请人/被指定审批人 | 发起领用/借用/调拨/变更、审批定向单、我的持有查询 |
| 部门负责人（规划） | 部门资产总览 | 部门维度台账/对账单 |

### 4.2 权限执行点 ✅

- **认证**：comm_public_basic token 三连校验（checkToken→getAuth→userSystemAuth）+ 30s Caffeine 缓存；无 asset 角色 403。
- **业务门禁**：审批人 ≠ 申请人（防自审自批）；assignee 非空时仅指定处理人可操作；撤销/盘点取消仅发起人；归还/调拨确认做资产合法性终检。

## 5. 全生命周期流程（一件资产的一生）

### 5.1 入库建档 ✅

资产管理员 `POST /api/v1/assets`：分类前缀自动生成编码（如 `SKSCDM-20260827-0001`）、状态强制 IDLE、写"新增"日志。历史存量经 M08 迁移工具批量导入（563 资产 + 1773 日志，幂等 upsert）。

### 5.2 领用 / 借用（ARE/BOR）✅

```
员工发起（选资产 + 领用区域必填 + 可指定处理人）
  ├─ 校验：资产存在 / 无在途单占用 / 区域存在 / assignee≠自己且存在
  ├─ 资产 IDLE/IN_USE → PENDING_CONFIRM（锁定）
  └─ 定向单 → 站内通知 assignee
审批人（assignee 或共享池任何非发起人）
  ├─ 通过：资产 → IN_USE；user_id/user_department/位置=领用区域；插持有记录(type=RECEIVE/BORROW)；通知申请人
  └─ 拒绝：资产 → IDLE 回库；通知申请人（含原因）
```

**到人时刻**：审批通过的那一个事务内，`asset.user_id` 与持有记录同时落库。

### 5.3 退库 / 归还 ✅

`POST /api/v1/allocations/{id}/return`（领用退库与借用归还同入口，免审批）：

```
持有记录 returned_at=now → 资产 IN_USE→IDLE（写"归还"日志）
→ 条件清空 user_id（仅当仍=原持有人；已被调拨转让则不动，防误清）
```

### 5.4 调拨（ATR）✅

调拨 = 归属转移，两种终态：

| 调入填写 | 终态 | 持有动作 |
|---|---|---|
| 使用人（可+部门+区域） | IN_USE 人持有 | 旧持有闭环 + 新建 TRANSFER 持有 |
| 只部门 | IN_USE 部门持有（user_id=NULL） | 同上（部门持有） |
| 只区域 | IDLE 回库 | 旧持有闭环 + user_id 归零 |

确认人=调入方（非发起人）；确认时逐台校验存在且未报废。盘点差异修复也走此通道（source=INVENTORY_TRIGGERED）。

### 5.5 实物信息变更（AOC）✅

使用人/部门/位置/公司的**信息修正**（不改状态）：确认时更新归属字段，使用人变化则闭环旧持有 + 新建 CHANGE 持有——与调拨同标准，不留悬死持有。每台资产每个实际变化字段一行明细（before/after 展示值），供 AOC 单打印。

### 5.6 盘点（Stocktake）✅

```
创建（范围=位置子树/分类，账面快照落明细）→ 开始 → PDA 扫码（/scan 按条码）
  ├─ 任务内：实际位置 vs 账面 → MATCHED / LOCATION_MISMATCH / NOT_FOUND(盘亏)
  └─ 范围外已登记 → EXTRA(盘盈)；未登记 404
完成（剩余待盘批量盘亏 + 逐台写日志）→ 报告（五态汇总）
  └─ 一键生成调拨单：位置不符资产按实际位置分组 → INVENTORY_TRIGGERED ATR 单
```

盘点闭环了"账实相符"：位置错 → 自动调拨归位；盘亏 → 留痕待人工追责。

### 5.7 报废 ✅

`POST /api/v1/assets/{id}/discard`（IDLE/IN_USE 均可）：IN_USE 报废**自动闭环持有 + 清空持有人**，日志记原持有人——修复过"在用报废悬死持有"缺陷（Ciyo 同类系统此场景会静默错账）。DISCARD 为终态。

## 6. 责任到人专项机制

### 6.1 个人持有台账 ✅

- 员工视角：`GET /api/v1/allocations?userId=我&active=true` → 我名下持有清单；工作台 `myHoldingCount`（B3）入口直达。
- 管理员视角：任意 userId 的历史持有（active=false）追溯"这人经手过哪些资产"。

### 6.2 离职 / 转岗资产清算 ⬜（规划，建议 P1）

**现状缺口**：员工离职后其名下资产仍挂 user_id，无强制清算动作。

**方案**（复用现有能力，增量小）：

1. 新增"人员对账单"页面：按 userId 拉持有中清单（现有接口即可支撑，前端工作为主）；
2. **离职联动**（需 comm_public_basic 离职事件或管理员手动触发）：`POST /api/v1/users/{id}/clear`——校验该用户无 PENDING 单据 → 名下持有中资产批量走"归还"通道（闭环持有 + 资产回 IDLE）→ 输出清算报告；
3. 防孤儿单：该用户作为 assignee 的 PENDING 单提示改派。

### 6.3 定期对账确认 ⬜（规划，建议 P2）

持有人定期（如每季度）在移动端/工作台"确认名下资产清单"，写 `asset_log`（operation_type=对账确认）。目的：责任链条从"系统记录"升级为"本人签字确认"，纠纷时有据。依赖 PDA 端（Phase 4）或工作台确认卡。

## 9. 数据一致性与审计保障 ✅

| 机制 | 保障 |
|---|---|
| 全链路 `@Transactional(rollbackFor)` | 单据/资产/持有/日志/通知同生共死 |
| 状态机硬校验 | 台账状态永远合法，对账可信 |
| 单号 `FOR UPDATE` 串行取号 + 唯一键 | 并发不重号 |
| 三单 PENDING 互斥占用 | 一物不二主 |
| 归还条件清空（user_id=原持有人） | 资产已转让不误清 |
| 审批门禁三层（非发起人/assignee/状态） | 防自审、防越权、防重复审批 |
| 姓名快照模式 | 组织变动不篡改历史 |
| 逻辑删除 + 自动填充 | 软删可审计 |
