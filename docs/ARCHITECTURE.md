# 架构概览

## 系统架构

这是一个前后端分离的 Web 应用，采用经典的三层架构。

```
┌─────────────────────────────────────────────────────┐
│                    用户层                            │
│  PC 浏览器  │  移动浏览器  │  钉钉客户端            │
└─────────────────────────────────────────────────────┘
                         ↓
┌─────────────────────────────────────────────────────┐
│                  前端层 (Nginx)                      │
│  Vue 3 SPA  │  路由  │  状态管理  │  组件库         │
└─────────────────────────────────────────────────────┘
                         ↓
┌─────────────────────────────────────────────────────┐
│              应用层 (Spring Boot)                    │
│  Controller  │  Service  │  Repository              │
│  统一鉴权  │  审批引擎  │  钉钉集成                │
└─────────────────────────────────────────────────────┘
                         ↓
┌─────────────────────────────────────────────────────┐
│                  数据层 (MySQL)                      │
│  资产表  │  单据表  │  审批表  │  用户表            │
└─────────────────────────────────────────────────────┘
                         ↓
┌─────────────────────────────────────────────────────┐
│                外部服务 (钉钉)                       │
│  免登  │  审批流  │  消息推送  │  通讯录            │
└─────────────────────────────────────────────────────┘
```

## 核心模块

### 资产管理模块
- **资产主表**：存储资产基本信息（编号、名称、分类、位置、状态）
- **状态机**：管理资产状态流转（空闲 → 在用 → 借用 → 维修等）
- **历史追溯**：通过单据关联查询完整轨迹

### 单据流程模块
- **领用/借用单**：员工申请使用资产
- **调拨单**：资产跨部门/跨地点转移
- **变更单**：修正资产信息
- **退还流程**：借用到期自动提醒

### 审批引擎
- **灵活配置**：支持多级审批、并行审批
- **双向同步**：站内审批 ↔ 钉钉审批实时同步
- **回调处理**：钉钉审批结果通过 Stream 推送

### 权限管理
- **角色体系**：资产管理员、仓管员、普通用户
- **功能权限**：控制菜单和按钮可见性
- **数据权限**：（规划中）控制可见数据范围

## 数据流转

### 典型场景：员工领用资产

1. **用户操作**：前端填写领用申请（资产选择、领用原因）
2. **提交请求**：POST `/api/v1/receipts` → 后端创建单据
3. **触发审批**：
   - 如果启用钉钉，推送审批实例到钉钉
   - 否则走站内审批流程
4. **审批处理**：
   - 钉钉审批：审批人在钉钉待办中处理
   - 站内审批：审批人在系统中处理
5. **状态同步**：
   - 钉钉回调 → 更新单据状态 → 更新资产状态
   - 站内审批通过 → 同步更新钉钉待办
6. **通知推送**：
   - 站内通知：显示在通知中心
   - 钉钉消息：工作通知推送

## 技术选型理由

### 后端

**Spring Boot 3**
- 生态成熟，社区活跃
- 自动配置减少样板代码
- Spring Security 天然支持鉴权

**MyBatis-Plus**
- 比 JPA 灵活，比原生 MyBatis 方便
- 代码生成器提效
- 逻辑删除、乐观锁等开箱即用

**Flyway**
- 数据库版本控制
- 团队协作不会乱
- 环境迁移可重现

### 前端

**Vue 3 Composition API**
- 逻辑复用方便（hooks 模式）
- TypeScript 支持好
- 性能优于 Vue 2

**Vite**
- 开发时启动快，热更新快
- 原生 ES 模块，不打包直接跑
- 生产构建用 Rollup，体积小

**Ant Design Vue**
- 组件丰富，质量高
- 企业级 UI，不用从零设计
- 中后台场景最佳实践

## 部署架构

### 开发环境
```
localhost:5173 (Vite Dev Server) → Proxy → localhost:6006 (Spring Boot)
```

### 生产环境
```
用户请求
  ↓
Nginx (80/443)
  ├─ /  → 前端静态资源
  └─ /api  → 反向代理到 Spring Boot (6006)
```

### Docker 部署
```yaml
services:
  mysql:      # 数据库
  backend:    # Spring Boot 应用
  frontend:   # Nginx + 前端静态文件
```

## 安全考虑

- **认证**：JWT Token，存储在 localStorage（计划迁移到 httpOnly Cookie）
- **授权**：基于角色的访问控制（RBAC）
- **CSRF**：前后端分离 + Token 机制天然防御
- **XSS**：Vue 默认转义 + CSP 头
- **SQL 注入**：MyBatis 预编译语句
- **敏感信息**：配置文件不入库，环境变量注入

## 性能优化

### 前端
- 路由懒加载：减少首屏加载时间
- 列表虚拟滚动：处理大数据量
- 防抖/节流：减少无效请求
- 静态资源 CDN：（规划中）

### 后端
- 数据库索引：主键、外键、常用查询字段
- 分页查询：避免一次性加载大量数据
- 缓存：（规划中）热点数据 Redis 缓存
- 连接池：HikariCP 高性能连接池

## 监控与运维

- **健康检查**：`/actuator/health` 端点
- **日志**：Logback 按日期滚动
- **错误追踪**：（规划中）接入 Sentry
- **性能监控**：（规划中）接入 Prometheus + Grafana

## 扩展性

### 水平扩展
- 前端：Nginx 静态文件，天然支持多实例
- 后端：无状态设计，支持负载均衡
- 数据库：主从复制、读写分离

### 功能扩展
- **插件化审批规则**：支持自定义审批流
- **多租户**：按公司隔离数据
- **工作流引擎**：引入 Camunda/Activiti 支持更复杂流程
