# M08 — 历史数据迁移

## 职责

将现有系统的 Excel 导出数据一次性导入新系统，建立历史数据基线。
迁移完成后新旧系统并行运行一段时间验证数据一致性，再切换。

## 数据规模

| 数据 | 来源文件 | 记录数 |
|---|---|---|
| 资产主数据 | AssetCard_20260818_165814.xlsx | 563 条 |
| 领用单 | Asset Receive Receipt_20260818_165715.xlsx | 346 条 |
| 调拨单 | 资产调拨单_20260818_165659.xlsx | 56 条（实际 56，含空行过滤）|
| 操作日志 | Asset History Logs_20260818_165840.xlsx | 1,775 条 |
| 闲置报告 | AssetOfStagnantReporQuery | 参考，不独立导入 |

## 迁移顺序（依赖关系决定）

1. 基础数据种子（company / category / location / manufacturer / supplier）
2. 资产主数据（asset）— 匹配 model_id（无 model 时先建占位 model）
3. 领用单主表（receive_receipt）+ 明细行（receive_receipt_item）
4. 调拨单主表（transfer_order）+ 明细行（transfer_order_item）
5. 操作日志（asset_log）— content 字段从 `【field】由【old】变更为【new】` 解析为 diff JSON

## 关键解析规则

**barcode 前缀 → 分类映射**（已知）：
- `SKSCDM` → 镀膜设备
- `SKSCFZ` → 辅助设备
- `SKSCJC` → 检测设备
- `SKBGDN` → IT设备/数码产品
- `SKQXCS` → 辅助设备（环保类）
- `SF` 前缀 → 归属 SF 公司（在 company 表独立建行）

**operator 字段拆解**：格式 `部门 工号 姓名` 或 `工号 姓名 角色`，
正则提取工号（`SK\d+`），匹配 comm_public_basic 用户表，
匹配不到时 operator_label 保留原始字符串，user_id 留空。

**area_name 路径解析**：`森科/PMC部/森科物料仓` → 按 `/` 分割，
逐级在 asset_location 表中 upsert，构建树结构。

**status 映射**：

| Excel 原值 | 新系统枚举 |
|---|---|
| Idle | IDLE |
| In Use | IN_USE |
| Discard | DISCARD |
| Receive Pending Confirm | PENDING_CONFIRM |

**调拨单操作人 "+盘点" 后缀**：剥离 `+盘点` 后再提取工号；
`transfer_order.source` 置为 `INVENTORY_TRIGGERED`。

## 实现方式

推荐 Java 迁移程序（而非纯 SQL），放在 `asset-backend/src/main/resources/migration/`
或独立的 `migration-tool/` 子目录：

- 读取 xlsx（Apache POI）
- 按上述规则转换
- 通过 service 层方法（而非直接 mapper）写入，自动触发 asset_log 记录
- 提供幂等性：重复运行不产生重复数据（按 barcode / serial_no 做 upsert）

## 验证清单

```

```
