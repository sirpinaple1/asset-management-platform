# M03 — 资产主表 CRUD + 状态机

## 职责

资产全生命周期管理：新增、查询、编辑、报废，以及核心状态机流转。
这是整个系统的数据中心，M04/M05 的状态变更最终写回此表。

## 涉及的表

| 表 | 操作 |
|---|---|
| `asset` | 主表，全量读写 |
| `asset_allocation` | 每次状态变更同步更新持有关系 |
| `asset_log` | 每次状态变更自动写入（service 层内置，非独立模块） |

## 状态机

```
[新增] → IDLE（闲置）
IDLE   → IN_USE          （领用，由 M04 触发）
IDLE   → DISCARD         （直接报废）
IN_USE → IDLE            （归还，由 M04 触发）
IN_USE → DISCARD         （在用中报废）
IDLE / IN_USE → PENDING_CONFIRM （发起领用申请后，由 M04 触发）
PENDING_CONFIRM → IN_USE （审批通过，由 M04 触发）
PENDING_CONFIRM → IDLE   （审批拒绝，由 M04 触发）
```

状态变更除"新增"外，均不由 AssetService 自行触发——M04/M05 的 service 调 AssetService 提供的
`changeStatus(assetId, newStatus, operatorId, note)` 方法，该方法同时写 asset_log。

## 对外 API

```
GET    /api/v1/assets                     # 分页列表，支持多条件筛选
GET    /api/v1/assets/{id}                # 详情
POST   /api/v1/assets                     # 新增（状态自动设为 IDLE）
PUT    /api/v1/assets/{id}                # 编辑基础信息（不含状态变更）
POST   /api/v1/assets/{id}/discard        # 报废
GET    /api/v1/assets/{id}/logs           # 该资产的操作日志
GET    /api/v1/assets/export              # 导出 Excel（对齐现有 AssetCard 格式）
POST   /api/v1/assets/import              # 批量导入（历史数据迁移入口）
```

## 关键查询条件（对齐 Excel 中实际使用的过滤维度）

`status / categoryId / locationId / companyId / userId / adminUserId / keyword（barcode/name/sn）`

## 依赖

## 完成标准

```
mvn clean verify 通过
POST /api/v1/assets → 201，barcode 唯一约束生效
GET  /api/v1/assets?status=IDLE&categoryId=1 → 正确过滤
POST /api/v1/assets/{id}/discard → 状态变 DISCARD，asset_log 有记录
PUT  /api/v1/assets/{id}/status 直接调用 → 405（状态只能通过业务接口变更）
```
