# M04 — 领用单（ARE）审批流

## 职责

资产领用申请的完整审批流：申请→审批（批准/拒绝）→资产状态联动。
对应现有系统 ARE 单，346 条历史数据。

## 涉及的表

| 表 | 操作 |
|---|---|
| `receive_receipt` | 领用单主表（ARE单） |
| `receive_receipt_item` | 领用单明细（一单对多资产） |
| `asset` | 审批通过时 status: IDLE→IN_USE；拒绝时 status: PENDING_CONFIRM→IDLE |
| `asset_allocation` | 审批通过时新增持有记录 |
| `asset_log` | 领用/归还操作写入日志 |

## 状态机

```
（申请人提交）→ PENDING
PENDING → APPROVED  （审批通过：资产 IDLE/PENDING_CONFIRM → IN_USE）
PENDING → REJECTED  （拒绝：资产 PENDING_CONFIRM → IDLE）
```

## 对外 API

```
POST   /api/v1/receipts                  # 发起领用申请（一次可申请多台资产）
GET    /api/v1/receipts                  # 列表，支持 status/date/userId 筛选
GET    /api/v1/receipts/{id}             # 详情（含明细行）
POST   /api/v1/receipts/{id}/approve     # 批准（需有审批权限）
POST   /api/v1/receipts/{id}/reject      # 拒绝，body={reason}
```

## 业务约束

- 同一资产同时只能有一张 PENDING 状态的领用单（提交时校验）
- 审批人与申请人不能是同一人（或由权限体系控制，以 comm_public_basic 角色为准）
- 批准时对每台资产调 `AssetService.changeStatus(id, IN_USE, ...)`，事务内完成
- 领用单的 `serial_no` 格式：`ARE` + `yyyyMMdd` + 4位序号，当天自增生成

## 归还入口

归还操作不单独建单据（与现有系统保持一致），通过 `asset_allocation` 更新 `returned_at` 并调
`AssetService.changeStatus(id, IDLE, ...)` 实现：

```
POST /api/v1/allocations/{id}/return     # 归还，asset status: IN_USE → IDLE
```

## 依赖

## 完成标准

```
mvn clean verify 通过
POST /api/v1/receipts → 201，相关资产 status 变 PENDING_CONFIRM
POST /api/v1/receipts/{id}/approve → 资产 status 变 IN_USE，asset_allocation 有记录，asset_log 有记录
POST /api/v1/receipts/{id}/reject → 资产 status 回 IDLE
同资产重复提交领用申请 → 409 Conflict
```
